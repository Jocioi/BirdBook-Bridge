# 波斑鸨插件 · BirdBook Bridge（BBB）

当前版本：**1.3.3**。

**把原片中 Lightroom 没有带出的拍摄信息，补进导出成片。**

波斑鸨插件（BirdBook Bridge，简称 BBB）是一个 Lightroom Classic 导出后处理插件，源自「LR小鸟书信息补全」。它从对应的索尼原片读取拍摄设置，写入导出文件，方便小鸟书（BirdBook）或其他支持相应元数据的软件读取。

官网与下载：[bird.uioiu.com/BirdBook-Bridge](https://bird.uioiu.com/BirdBook-Bridge)。

先了解用途、支持范围和使用边界，可阅读 [中文项目说明](项目说明.md)。

产品目标不限定输出格式；**当前实现 JPEG、TIFF、PNG**，并通过文件级测试；Lightroom 界面验收仍待完成。其他格式规划见项目说明，未验证的格式不列为已支持。

## 当前支持范围

- **macOS 13 或更新版本**；参考框辅助程序可从源码构建为 Apple Silicon / Intel 通用二进制。
- **Lightroom Classic**，使用导出后处理动作；不是 Lightroom 云端版、手机版或网页版插件。
- **Sony α1 II / ILCE-1M2，ARW 或相机 JPG/JPEG → JPEG、TIFF、PNG**。不要求来源一定是 RAW；相机 JPG 缺少的信息不会猜测补出。其他相机和格式尚未支持。
- 导出元数据必须选择 **「所有元数据 / All Metadata」**。其他设置会跳过补全，以尊重导出时的选择。
- 来源文件必须在线。虚拟副本使用对应原始文件；相机 JPG 可直接作为来源，但其已丢失的信息无法凭空恢复。

## 能补什么

| 信息 | 保存方式 |
| --- | --- |
| 相机、镜头、曝光时间、光圈、ISO、焦距、35mm 等效焦距、曝光补偿、曝光模式、测光、闪光、白平衡等 | 原片有值、导出文件缺失时补入标准 EXIF；已有值保留 |
| 估计对焦距离 | Adobe XMP `aux:ApproximateFocusDistance`；已有值保留 |
| 对焦模式、所选及实际对焦区域、追踪、防抖、驱动模式、电子前帘、白平衡微调、色温、降噪、色彩、相机固件、APS-C 开关、机内校正与原片信息等最多 51 项 | 自定义内嵌 XMP `bbinfo`，保留拍摄时设置和来源信息 |
| 原片对焦坐标、框尺寸、方向、距离编码 | 自定义内嵌 XMP，保留来源信息 |
| 可可靠换算的对焦框；轻微镜头校正后的参考框 | 自定义内嵌 XMP `bbfocus`，明确区分实际坐标换算与参考估计 |

LR 已导出的标准字段由读取软件直接使用，BBB 不重复保存；只有缺失项或语义更细的拍摄设置才补充。51 项是可选字段总数，不代表每张照片都有 51 项；原片没有的值会省略。

原始文件名优先使用 LR 的 `crs:RawFileName`，缺失才另存；星级优先使用 LR 的标准 XMP，缺失才补相机星级。原片大小和类型与成片区分保存。拍摄日期、毫秒和时区直接读取已有字段；曝光值由曝光参数计算，不重复写自定义字段。

完整字段及格式见 [元数据说明](docs/METADATA.md)。

### 为什么不是全部写成标准 EXIF？

标准 EXIF 的字段有特定含义。基础曝光参数有对应字段；索尼的动物眼部追踪、实际 AF 区域等没有等价的通用字段。EXIF 的 `SubjectArea` / `SubjectLocation` 表达主被摄体区域或位置，并不能完整表达相机 AF 框及校正后的估计状态。把这些数据塞进不对应的字段，会使读取软件误解。

标准 EXIF 确实有 `SubjectDistance`。本插件的距离来自索尼距离编码及 ExifTool 计算，是**估计值**，因此使用已有的 Adobe `ApproximateFocusDistance` 字段，避免丢失“估计”语义。XMP 与 EXIF 都内嵌在同一个 JPG 中，无需额外 sidecar；普通软件可能只显示它认识的字段。

## 安装和使用

首次完成三步：

1. **添加插件。**从 [Releases](https://github.com/Jocioi/BirdBook-Bridge/releases) 下载 `BirdBook-Bridge-1.3.3.zip` 并解压，将 `BirdBookBridge.lrplugin` 放到固定目录，在 Lightroom Classic → **文件 → 增效工具管理器 / Plug-in Manager → 添加** 中选择并启用。也可按下节从源码构建。
2. **加入导出流程。**在导出窗口的 **后期处理动作 / Post-Process Actions** 中插入 **波斑鸨插件 (BBB)**。
3. **保存预设。**选择 **JPEG、TIFF 或 PNG**，元数据选择 **所有元数据 / All Metadata**，保存为自己的导出预设，例如「BBB 信息补全」。

之后只需：**选照片 → 选择 BBB 导出预设 → 导出**。无需手动配对原片或逐项勾选补充字段。

GitHub 自动生成的 **Source code** 压缩包需要自行构建；直接安装请选择带版本号的插件 ZIP。

安装插件本身不等于每个导出预设都会自动使用它。每批结束会显示已补全、部分补全、未补全和失败数量；部分补全可能是未添加对焦框。正常结果短暂显示，遇到未补全或失败只按批次提示一次，并说明原因。不会擅自改掉你的元数据隐私选择。

旧版插件与 BBB 保留同一个 Toolkit ID 和 XMP 命名空间，以兼容已有数据。**不要同时启用旧版和 BBB**；迁移时先停用旧版，再添加 BBB，并检查已有导出预设是否包含新的动作。ZIP 不含个人导出路径或现成预设。

## 小鸟书中的显示

新导出的照片重新导入后，相机和镜头型号显示在各自详情行右侧；相机固件只显示版本号。拍摄摘要依次为快门、光圈、ISO、焦距；索尼明确开启 APS-C 时，摘要显示实际焦距 × 1.5，并标为「等效焦距」。这只改变页面显示，照片里的实际焦距不变。曝光补偿放在「曝光详情」右侧，展开后不重复；重复的镜头规格行隐藏。其他设置按类别折叠，只显示实际读到的信息。

## 从源码构建

需要 macOS、Xcode Command Line Tools（`xcode-select --install`）、系统 Perl、Python 3。ExifTool 13.55 的原始 Perl 库已随项目提供，构建和运行均无需下载依赖。

```sh
sh scripts/build.sh
sh scripts/test.sh
```

构建结果：`dist/BirdBookBridge.lrplugin` 和 `dist/BirdBook-Bridge-1.3.3.zip`。辅助程序分别编译 arm64 / x86_64，再合成通用二进制。构建脚本不安装插件，也不修改 Lightroom 设置。

本项目提供源码及本地构建产物，不含 Apple 开发者分发签名或公证。请按系统正常安全流程处理下载提示，不要全局关闭安全保护。

## 对焦框的边界

- 原片必须具有有效的自动对焦模式、坐标和框尺寸；不会靠识别鸟的位置来编造对焦框。
- 普通缩放、符合条件的矩形裁切和方向变换可以直接换算；框不完整落在裁切区内时不输出。
- **轻微镜头配置文件校正**可以尝试将原片内嵌预览与导出成片匹配，成功时输出 **参考对焦框**。它是估计位置，不能用于证明像素级对焦精度。
- 旋转裁切、透视调整、手动畸变、已校正的相机预览等组合仍有保护限制；低纹理、不匹配或无法可靠验证的图片不会输出参考框。
- 参考匹配每张最多等待约 10 秒；失败时仍可保留其他拍摄设置和明确的状态。
- 相机 JPG 已可能经过机内几何校正；当前只保留其已有拍摄信息，暂不生成对焦框，避免误画。
- 已导入小鸟书的旧文件不会自动更新，须重新导出并导入。

## 数据与隐私

运行时只在本机读取原片、处理导出副本；无网络请求、遥测或上传功能。不会修改来源文件。JPEG、PNG 的压缩画面数据和 TIFF 的像素须保持完整；已通过生成图像的逐像素检查，包括 PNG 透明度与 16 位 TIFF。只选择性补充字段，不整包复制 MakerNotes；不恢复已去除的 GPS、人物、序列号或版权信息。导出时原本保留的这些信息也不会被本插件清除，请自行选择合适的 Lightroom 导出元数据策略。

## 验证与贡献

测试使用程序生成的图像，不含真实照片、位置或拍摄者信息。见 [验证记录与限制](docs/VALIDATION.md)。贡献支持新相机时，请先提供字段语义和可重复的验证，避免仅按类似名称映射。

提交问题时可提供相机、系统和 Lightroom 版本，以及脱敏后的字段。不要上传带有 GPS、人物信息或版权限制的原片。
